# V1.6.11 — аудит интерфейса и активности полей

Основание: ТЗ системной переработки UI/UX программы «Отчётность УК», восемь скриншотов реального Windows-интерфейса при размере 1666×896, актуальная кодовая база V1.6.10 и приложение № 2 к приказу Минстроя РФ от 20.11.2025 № 728/пр.

## Подтверждённые дефекты

| Раздел | Что видно на предоставленном экране | Причина в коде | Меры |
|---|---|---|---|
| УО | Неактивные реквизиты на пустом экране, слишком узкие подписи | Нет выбранной УО; длинные QLabel с WordWrap в QFormLayout | Явный начальный экран «создайте УО»; выравнивание подписей и контроль их ширины |
| Дома | Пустой перечень, серые поля, скомканные названия реквизитов | Не выбрана УО/дом; поля отключены штатно, но нет пояснения | Контекстная пустая карточка; доступ к добавлению дома только после выбора УО; единая геометрия форм |
| Категории | Таблица подкатегорий использует половину ширины; узкие подписи | `resizeColumnsToContents` без растягивающихся столбцов, WordWrap | Растягивание наименования и примечания; выровненные поля |
| Справочник | На огромной площади справа пусто, наименования обрезаны | Таблица со статичными ширинами без stretch | Распределение ширины по текстовым столбцам; подсказки в ячейках |
| Шаблоны | Один шаблон виден, но его поля всё ещё серые | `TemplatesTab.refresh` не выбирал единственную запись | Автоматический выбор единственного шаблона; экран «Выберите шаблон» при отсутствии выбора |
| Массовое заполнение | Неочевидный выбор домов; крупные пустые области | Без УО нет домов; две формы с рваными подписями, таблица с фиксированной шириной | Выравнивание подписей, полная ширина предпросмотра; защита прокрутки отчетного года |
| Отчёты | Большая пустая область справа и кнопка сохранения без отчёта | Табличный редактор скрыт, но отдельная кнопка сохранения/заголовок оставались | Карточка «Отчёт пока не выбран»; скрытие неактуальных действий, раскрытие всех вкладок после выбора |
| Резервные копии | Огромная белая таблица при нуле копий; кнопки кажутся неактивными | Список архивов растягивается даже при нуле записей | Компактное пустое состояние с инструкцией; защита подсветки отключённых кнопок |

Наличие серого поля **до создания записи** — предусмотренное поведение. Дефект состоял в том, что интерфейс выглядел как неработающий даже при отсутствии объекта. Дом по-прежнему не может произвольно сменить УО в своей карточке: привязка защищена во избежание некорректных отчётов.

## Проверка обязательных полей официальной формы

Сопоставление с приложением № 2:
- **Шапка:** год, адрес МКД, полное наименование УО, ОГРН/ИНН, адрес приёма населения, лицо для разъяснений, телефон/e-mail, общая площадь, дата размещения — имеются в карточках УО, дома и общих сведениях отчёта;
- **1. Содержание:** наименование, единица измерения, цена, количество и стоимость по перечню, фактически выполненное количество и стоимость — таблица `content_table`;
- **2. Текущий ремонт:** сальдо на начало/конец, начисления, стоимость работ; наименование, основание, стоимость, объём, реквизиты акта/ссылка — таблица `repair_table` и поля раздела;
- **3. Управление:** официальная итоговая стоимость; внутренние строки расчёта не подменяют итог автоматически — `management_cost`;
- **4. Претензионная работа:** число претензий, заявлений/приказов, сумма поступлений — `claim_pret`, `claim_lawsuits`, `claim_amount`;
- **5. Финансы:** два вида плательщиков, задолженность на начало/конец, начислено и поступило — `finance_table`.

**Важно:** наличие виджетов в коде и прохождение автоматических тестов **не доказывает**, что конечный документ полностью совпадает с нормативным бланком по оформлению. Для этого необходима отдельная визуальная и юридическая приёмка экспорта на реальных данных.

## Принципы тестирования V1.6.11

- В каждом разделе испытать состояния «объект не выбран» и «объект создан/выбран».
- Проверить доступность полей, изменение и сохранение значений в изолированную тестовую БД.
- Проверить реальную возможность редактирования и блокировку только защищённых полей, особенно видов плательщиков.
- Проверить, что вставка нескольких строк из буфера создаёт записи с корректными служебными данными, а в фиксированной финансовой таблице не создаёт дополнительного плательщика.
- Для категории, справочника, шаблона и отчётных таблиц сверить ширину суммы видимых столбцов с шириной их viewport.
- В Windows CI формировать снимки наполненных и пустых экранов в двух темах при обычном и моделируемом высоком DPI. Отдельно проверять настоящий экран Windows.

## Проверка оставшихся функций по репозиторию

| Компонент | Охват |
|---|---|
| `db.py`, `paths.py`, `backup_restore.py` | Схема, ссылки, копии, повторный запуск, восстановление |
| `report_storage.py`, `report_review.py` | Сохранение разделов и проверка перед выгрузкой |
| `mass_apply_logic.py` | Атомарное массовое заполнение, защита ручных строк, состояние предпросмотра |
| `exporters.py` | Вывод пяти разделов в DOCX/XLSX/PDF, обязательные реквизиты и суммы |
| `ui_shell.py`, `ui_style.py`, `ui_components.py` | Ширина навигации, структура форм, ширина таблиц, отображение кнопок |
| `app.py` | Поля всех восьми страниц, события, сохранение, переключения, копирование/вставка |

Проверки тестируют код в Windows CI и тестовой SQLite. Финальное подтверждение удобства — исключительно в реальной пользовательской сессии Windows.

## Что не входит в этот этап

- Новые интеграции, ГИС ЖКХ и объединение баз других программ;
- изменение официальных формул и структуры приложения № 2;
- замена интерфейса изображением или механическое копирование приложения-референса;
- автоматическое изменение принадлежности МКД к управляющей организации.
