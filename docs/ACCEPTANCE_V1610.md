# Приёмка V1.6.10 — безопасное восстановление данных

Версия: V1.6.10, дополнение к историческому документу [этапа Е](ACCEPTANCE_STAGE_E.md).

## Сценарий восстановления

1. Закройте работу над отчётами и перейдите в «Данные и резервные копии».
2. Выберите копию из списка (или внешний файл .db) и нажмите «Проверить выбранную».
3. Программа проверяет SQLite integrity_check, обязательные таблицы, схему и поддерживаемую версию. Неверная, чужая или слишком новая база отклоняется.
4. Нажмите «Восстановить выбранную», ознакомьтесь с количеством УО, домов и отчётов, подтвердите подготовку. Текущая база пока не заменяется.
5. Закройте программу и запустите заново. **До запуска интерфейса** программа проверит неизменность снимка по SHA-256, сохранит текущую базу в защитную копию `reporting_728_before_restore_*.db` и только затем восстановит выбранный снимок через механизм SQLite backup.
6. При ошибке приложение не должно открывать потенциально повреждённую базу. Копия текущей базы остаётся в `data/backups`. До перезапуска заявку можно отменить.
7. После запуска сверьте данные выбранных УО, дома и отчёты с резервной копией.

**Не удаляйте вручную папку `data` и файлы `-wal`/`-shm`.** Перемещайте только EXE при обновлениях. Перед использованием с реальной базой дополнительно сохраните отдельную копию всей папки `data` с закрытой программой.

## Автоматическая защита

- Резервная копия создаётся SQLite online backup API, включая транзакции из WAL, с проверкой целостности.
- Автоматически очищаются только старые `reporting_728_auto_*.db`; пользовательские и защитные копии не удаляются по лимиту.
- Проверяются: отказ при повреждённой базе, неизвестная схема, будущая версия базы, подмена отложенного файла, нехватка места для защитной копии, отмена, корректное сохранение текущей базы до восстановления.
- Снимки 11 экранов в двух темах при обычном Qt и моделируемом высоком DPI 125/150% (66 PNG). Это **симуляция Qt масштабирования**, а не подтверждение работы при системном масштабе реального монитора Windows.

## Что по-прежнему требует ручной приёмки

- Открытие окон, читаемость форм и реакция мыши/клавиатуры на Windows с реальным DPI 100/125/150%.
- Выбор восстановленной базы, перезапуск EXE, сверка нескольких УО, МКД и отчётов на копии реальных данных.
- Подробная сверка подготовленных DOCX, XLSX, PDF с макетом приложения № 2 приказа Минстроя России № 728/пр; автотесты не подтверждают юридическое соответствие документов.
- ГИС ЖКХ и общая БД других программ в текущем продукте по-прежнему не подключены.
