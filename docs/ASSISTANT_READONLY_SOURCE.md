# Общая база «ГИС ЖКХ Ассистента»: подключение только для чтения

С версии **1.6.14** «Отчётность УК» может использовать сведения о управляющих организациях и домах из локальной базы программы [ГИС ЖКХ Ассистент](https://github.com/serbo26-lab/gis-jkh-assistant).

## Где находится база

По умолчанию на Windows: `%LOCALAPPDATA%\\GIS JKH Assistant\\data.db`.

Если «Ассистент» установлен в другой папке или использует нестандартное расположение, откройте в «Отчётности УК» раздел **«Данные и резервные копии» → «Общая база ГИС ЖКХ Ассистента» → «Выбрать базу Ассистента…»**, укажите файл `data.db` и подтвердите подключение.

В этом же разделе кнопка **«Обновить сведения из Ассистента»** перечитает источник. При следующем запуске «Отчётчик» повторяет обновление автоматически, если файл доступен. Если источник недоступен, уже существующие локальные отчёты продолжают открываться; данные не удаляются.

## Что именно читается

- Управляющие организации: стабильный идентификатор, наименование, ОГРН.
- Дома: стабильный идентификатор, привязка к УО, адрес, начало и окончание управления, отдельные площади жилых и нежилых помещений, их сумма (если известны обе составляющие), номер и дата договора управления.
- Подписанты УО и представители собственников по дому: список записей из `act_people` с ФИО, ролью, основанием, должностью, датами полномочий и склонением. Файлы изображений подписей **не копируются**.
- В текущей схеме «Ассистента» нет самостоятельных полей начала/окончания **действия договора** — их можно заполнить локально в «Отчётчике». Они не выводятся автоматически из периода фактического управления.
- Площадь для начисления платы (`charge_area`) **не подменяет** официальную площадь жилых и нежилых помещений.
- Пока этот этап **не загружает автоматически** тарифы, перечни работ, планы, фактические объёмы и финансовые расчёты из «Ассистента»: они потребуют отдельного сопоставления с пятью разделами формы приказа № 728/пр. Автоматически относить данные к неправильным строкам формы нельзя.

## Куда сохраняются записи

**Ни одна команда «Отчётчика» не выполняет INSERT, UPDATE, DELETE или ALTER в базе «Ассистента».** Она открывается `sqlite3.connect(..., uri=True)` с `mode=ro`, дополнительно используется `PRAGMA query_only=ON`. «Отчётчик» не запускает миграции, настройку WAL или создание базы в каталоге «Ассистента». SQLite при работе с WAL может обращаться к служебным файлам `-wal` и `-shm`; содержимое записей исходной базы не изменяется.

«Отчётчик» использует собственную базу `data/reporting_728.db`. В ней сохраняются связи со стабильными текстовыми идентификаторами УО/домов «Ассистента» и локальные записи для отчёта. Числовые ID отчётов не заменяются, их связи сохраняются. При обновлении источник сверяется по ID, а не по совпадению названия/адреса.

- Для связанных УО **название и ОГРН** редактируются только в «Ассистенте». Сведения о приёме населения, ответственный за разъяснения, контакты и примечания сохраняются только в «Отчётчике».
- Для связанных домов **адрес, период управления, номер и дата договора, известные площади помещений** берутся из «Ассистента». Статус, примечания и сроки действия договора — локальные. Если одна или обе составляющие площади отсутствуют, «Отчётчик» позволяет дополнить отсутствующее значение локально. При наличии двух составляющих общая площадь вычисляется автоматически; старое общее значение не стирается, пока составляющие не заполнены.
- Подписанты разделены на два самостоятельных реестра: УО и представители дома. Записи из «Ассистента» показываются только для просмотра. Внутри «Отчётчика» можно вести дополнительные локальные записи с датами действия полномочий, не изменяя источник. Старые записи не удаляются автоматически при исчезновении из источника.
- Исторический отчёт не удаляется, если УО или дом исчезли из Ассистента: последний локальный снимок остаётся доступным.
- Если дом с уже созданными отчётами в «Ассистенте» передали другой УО, обновление отклоняется **целиком**, чтобы не нарушить связи отчётов.
- Перед явным и автоматическим обновлением создаётся отдельная защитная копия **собственной** базы Отчётчика.

**Режим этой версии:** одностороннее чтение УО, домов, их реквизитов и подписантов; запись отчётов и локальных дополнений только в собственную SQLite. Сам факт хранения подписанта не означает подписания им документа. Автоматическая вставка подписей в DOCX/PDF пока не включена и будет проектироваться отдельно с выбором лица и периода полномочий.

Это не ГИС-синхронизация и не объединение схем двух приложений.
